왼쪽 칸은 문서가, 오른쪽 칸은 내가.

● ◐ ╱ · — 이건 문서에서 자동으로 찍힌다. 칸에 내용을 적으면 ●, "확인 못함"이 섞이면 ◐, "확인 못함"으로 시작하면 ╱, 블록이 아예 없으면 ·. 누를 수 없고, 누를 이유도 없다.

오른쪽 끝 네모 — 이건 내가 켠다. “여기는 더 볼 일 없다”는 뜻이다. 문서에 없던 정보라 겹치지 않는다.

왼쪽은 색이 없고 오른쪽 체크만 색을 가진다 — 이 아카이브의 규칙이 “색은 사람이 손댄 흔적”이라서다.

정함 — 노랑만

⑤ 표시를 몇 가지 둘까

정함 — 한 가지

노란 ✓ 말고 다른 표시를 하나 더 둘 것이냐는 물음이다. 아래 줄을 눌러 보면 차이가 바로 보인다.

한 가지 — ✓ 하나만 ✔

고른 안 · 누르면 켜지고, 다시 누르면 꺼진다

  • ●동의서
  • ●저작권
  • ◐공개등급
  • ●열람절차
  • ╱2차활용

✓ = 더 볼 일 없다.
안 켠 것 = 아직 판단 안 함 = 다시 봐야 함.

판단 한 번 · 상태 2가지 · 색 하나

두 가지 — ✓ 와 ↻

안 쓰기로 · 누를 때마다 ✓ → ↻ → 꺼짐 으로 돈다

  • ●동의서
  • ●저작권
  • ◐공개등급
  • ●열람절차
  • ╱2차활용

✓ = 더 볼 일 없다.
↻ = 확인은 했지만 낡았다, 다시 볼 것.
안 켠 것 = 아직 판단 안 함.

판단 두 번 · 상태 3가지 · 색 둘

한 가지로 정했다. ↻로 찍고 싶은 것 — “대통령기록관 열람절차는 2019년 실태조사 자료라 낡았다” 같은 것 — 은 사실 그냥 ✓를 안 켜면 되는 일이다. 안 켠 칸이 이미 “다시 봐야 함”이라서, ↻를 만들면 칸마다 두 번 판단하게 된다. 15칸 × 52사업이다.

그리고 오른쪽에 색이 둘(노랑·주황)이 되면, 이 라벨에서 색이 지던 뜻 하나 — “내가 손댄 자리” — 가 둘로 갈라진다.

저장은 DB다. 앞서 파생 상태는 문서에 둬야 한다고 했던 것과 반대인데, 이유가 다르다 — 파생 상태는 문서 내용의 중복이라 갈리지만, 이 체크는 문서에 없던 새 정보라 갈릴 것이 없다. 코드에 이미 같은 패턴이 있다(is_important · highlighted).
